# 测试用例（全流程）

## 1. 测试范围

- 管理后台：登录、导入用户、设置兑换次数、查看订单、发货录入物流
- 用户端：三要素校验、短信验证码登录、加入购物车、结算提交订单、查看订单与物流
- 规则校验：库存不足、兑换次数不足、HR 码/姓名不匹配、未登录拦截

## 2. 环境与数据准备

- 运行方式：Render 线上环境或本地 Spring Boot（H2）
- 管理员账号：`admin / admin123`
- 测试用户白名单：后台导入 CSV（姓名、手机号、HR码）
- 短信验证码：测试环境为 mock，调用发送验证码接口会返回 `debugCode`

## 3. 手工测试用例

### TC-01 后台导入用户白名单

- 前置：管理员已登录后台
- 步骤：
  - 进入 `/admin` → 用户兑换次数管理 → 导入用户（CSV）
  - 上传 CSV：
    - `姓名,手机号,人力资源码`
    - `张三,13900000001,HR9999`
- 期望：
  - 返回导入成功（新增或更新计数正确）
  - 用户列表出现该手机号，且展示 hrCode

### TC-02 后台设置用户可兑换次数

- 前置：TC-01 已导入用户
- 步骤：
  - 在用户列表点击“设置次数”，输入 `5`
- 期望：
  - 页面显示可兑换次数=5，已用=0，剩余=5

### TC-03 用户三要素校验通过后发送验证码

- 前置：TC-01 已导入用户
- 步骤：
  - 打开 `/app/login.html`
  - 输入：姓名=张三，手机号=13900000001，HR码=HR9999
  - 点击“发送验证码”
- 期望：
  - 提示“验证码已发送”
  - 测试环境可获得验证码（debugCode 或日志）

### TC-04 用户三要素不匹配禁止发送验证码

- 前置：TC-01 已导入用户
- 步骤：
  - 姓名或 HR码 任意填错后点击“发送验证码”
- 期望：
  - 提示“姓名或人力资源码不匹配”

### TC-05 用户验证码登录成功

- 前置：TC-03 已获得验证码
- 步骤：
  - 输入验证码并登录
  - 进入 `/app`
- 期望：
  - 登录成功进入用户端首页
  - “剩余兑换次数”显示为后台设置值（例如 5）

### TC-06 购物车加入商品与修改数量

- 前置：用户已登录
- 步骤：
  - 在“兑换商品”选择数量，点击“加入购物车”
  - 到“购物车”修改数量、移除某一项
- 期望：
  - 合计消耗次数=购物车数量合计
  - 购物车刷新页面后仍存在（localStorage）

### TC-07 结算提交订单成功（拆单）

- 前置：购物车至少 2 种商品、库存充足、兑换次数充足
- 步骤：
  - 点击“去结算”
  - 填写收货人/手机号/地址
  - 点击“提交订单”
- 期望：
  - 提示下单成功
  - 购物车清空
  - 我的订单出现多条订单记录（与购物车商品种类一致）
  - 已用次数增加=购物车数量总和

### TC-08 结算兑换次数不足拦截

- 前置：后台将可兑换次数设置为较小值
- 步骤：
  - 购物车合计数量大于剩余次数
  - 点击“提交订单”
- 期望：
  - 提示“兑换次数已用完”
  - 不扣减次数、不扣减库存、不生成订单

### TC-09 结算库存不足拦截

- 前置：将某商品库存设为 0 或小于购物车数量
- 步骤：
  - 购物车包含该商品并提交
- 期望：
  - 提示“库存不足：{商品名}”
  - 不扣减次数、不扣减库存、不生成订单

### TC-10 后台发货并查看物流

- 前置：已有待发货订单
- 步骤：
  - 后台 `/admin` → 订单列表 → 发货
  - 输入快递公司与单号（例如：顺丰 / SF123456789）
  - 用户端“我的订单”点击“查看物流”
- 期望：
  - 后台订单显示“查看物流”链接与单号
  - 用户端同步显示物流链接
